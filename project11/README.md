# Personal Money Detective

A backward-looking investigation of your own wallet history: where the money went, what keeps
charging you, what may have been billed twice, and what will be left by your next pocket money.
Python does all the calculation, locally. No AI estimates any number, and nothing is uploaded.

## Run it

```
python my_monthly_money_check.py --input wallet_export.csv
```

The script uses this project's `.venv` automatically. On a new computer, first run:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Each run first reproduces known answers on the fictional sample wallet. If any check fails, it stops
and writes no report.

| Option | Meaning |
|---|---|
| `--input a.csv b.xlsx` | One or more exports (`.csv .tsv .txt .xlsx .json`). Overlaps count once. |
| `--next-pocket-money 2026-11-15` | Next pocket-money date. Inferred from a regular pattern if omitted. |
| `--current-balance 3200` | Balance now. Preferred, because it needs no assumptions. |
| `--opening-balance 6000` | Balance just before the first row. Only correct if the export is complete. |
| `--output-dir private_reports` | Report location (default `reports/`). |
| `--currency PKR` | Label only. Nothing is converted. |
| `--date-format mdy` | Use when `03/04/2026` means March 4. Default for ambiguous dates is day/month. |
| `--as-of 2026-10-30` | Forecast start date (default: last transaction). |
| `--include-irregular-income` | Count income with no rhythm in the forecast at its observed rate. |
| `--inspect` | Show how the file was understood, then stop. |
| `--export-sanitized DIR`, `--compare FILE` | Optional second-model check; see [docs/CROSS_MODEL_VERIFICATION.md](docs/CROSS_MODEL_VERIFICATION.md). |

## Using a real export

1. Put the file in `private/` (ignored by Git).
2. Check it was understood: `python my_monthly_money_check.py --input private\wallet.csv --inspect`
   This shows the columns matched, date format, period, balance, unreadable rows and any coverage gaps.
3. Run it with your currency, balance and pocket-money date. Read the report in `reports/`.

## How the numbers are made

- **Income:** money-in rows, leaving out refunds, adjustments and moves between your own accounts.
- **Spending:** money-out rows grouped by keyword rules on merchant names. Refunds reduce their category.
- **Repeat charges:** merchant, amount and days between charges are judged together.
  *Confirmed* needs 3+ dates, at least 80% of gaps on rhythm, and steady amounts. *Probable* covers
  subscription-type merchants with a changed price or only two charges, and two charges about a year
  apart. *Possible* is a partial rhythm for manual review.
- **Possible duplicates:** 2+ charges with the same date, merchant and amount. Close timestamps or a shared
  reference strengthen the evidence; hours apart, an often-repeated category, or a matching refund weaken it.
  Rows are never removed.
- **Biggest leak:** the largest net category classed as discretionary or potentially avoidable. Essentials never qualify.
- **Forecast:** spending from now until the day before the next pocket money.
  - *Expected:* confirmed scheduled charges + average variable spending per day.
  - *Conservative:* adds probable subscriptions, with a 75th-percentile week.
  - *Higher-spending:* adds probable subscriptions, with the most expensive week seen.
  - Income without a reliable rhythm is shown as a possible extra, not counted.

## Sample wallet

`data/sample_wallet.csv` is fictional, in fictional Credits (CR), generated by
`scripts/make_sample_wallet.py`. It covers 1 Jul to 30 Oct 2026 and pairs with `--opening-balance 6000`. It holds
raw rows only. The expected answers exist solely in `src/verification.py`, which compares them with what
the engine computes and recounts two of them from the raw rows without using the engine.

## Privacy

Everything runs locally and the original files are only read. The report has no scripts, and a
content security policy blocks external requests. Card and account-like numbers, IBANs and emails are masked
in outputs. `.gitignore` excludes exports and reports, except the synthetic sample. The project never asks for
passwords, PINs or card numbers, and it cannot log in to a bank or move money.

## Limitations

- Keyword categories can be wrong; unrecognized merchants land in *Other expenses*.
- Averages only reflect the file's period. A missing stretch makes them too low (a warning appears for gaps over 31 days).
- Annual charges need more than a year of history.
- Identical rows without a reference are always kept, since they could be a double charge. A wallet that exports
  true repeats with no reference will show them as possible duplicates rather than removing them.
- Mixed currencies are added with no conversion; a warning appears.
- A forecast is an estimate from past behaviour, never a guarantee.
